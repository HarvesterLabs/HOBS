HOBS Object Manager v0.1
STEP 01 — Data Model
Revision 3 Addendum 01
Delete起因 Relation Removed の記録境界
2026-09-22

======================================================================
0. Addendumの位置づけ
======================================================================

本Addendumは、

HOBS Object Manager v0.1
STEP 01 — Data Model
Formal Revision 3

に対する補足仕様である。

Revision 3本体をRevision 4へ改訂するものではない。

Revision 3本体のData Modelを維持したうえで、
主任ちゃんの実装監査により確認された
「Delete起因でRelationが消滅する場合のRelation Removedの記録境界」
について、本部判断を正式に明文化する。

本AddendumはRevision 3と一体として扱う。


======================================================================
1. 本Addendumで確定する範囲
======================================================================

本Addendumが対象とするのは、

    Deleteを原因としてRelationが消滅するケース

に限定する。

通常のRelation解除・Relation変更を対象とした一般則を変更するものではない。


======================================================================
2. 通常のRelation Removed
======================================================================

Revision 3のHistory仕様を維持する。

通常のRelation解除・変更によってRelationが削除された場合、

    Relation Removed

は、Revision 3で定義された
Relation固有のHistoryイベントとして扱う。

したがって、

    Relation Removed
    = 一般的なHistoryイベント

というRevision 3の原則は変更しない。


======================================================================
3. Delete起因のRelation Removed
======================================================================

次のケースを対象とする。

    Object A ──Relation──→ Object B

    AをDelete
        ↓
    AのHOBS Objectとしての存在終了
        ↓
    AをsourceまたはtargetとするRelationも存続不可
        ↓
    Relation消滅


この場合、

    Relation Removed

を存続するObject BのHOBS Object Historyには記録しない。


======================================================================
4. DeleteされたObjectのHistoryとの関係
======================================================================

DeleteされたObject Aについては、
Revision 3で確定しているDelete原則を維持する。

    AのHOBS Object History
        ↓
    AのObjectとともに消滅

したがって、DeleteによってRelationが消滅したことを
AのHOBS Object Historyへ残すこともしない。


======================================================================
5. 操作監査情報
======================================================================

Delete起因のRelation消滅について、
システム上、操作記録・監査情報・Undo等の情報を
別途保持する必要がある場合がある。

その場合、

    操作監査情報
        ≠
    HOBS Object History

として扱う。

操作監査情報は、
HOBS ObjectのHistoryとして扱わない。

また、操作監査情報の具体的なデータ構造・保存期間・
実装方式については、本Addendumでは定義しない。


======================================================================
6. 具体例
======================================================================

【通常のRelation解除】

    Object A ──Relation──→ Object B

    Relation解除
        ↓
    Relation Removed
        ↓
    Revision 3のHistory規則に従って記録


【Delete起因のRelation消滅】

    Object A ──Relation──→ Object B

    AをDelete
        ↓
    Relation消滅
        ↓
    BのHOBS Object History
        = Relation Removedを記録しない

    必要な操作記録
        ↓
    HOBS Object Historyとは別の監査情報


======================================================================
7. 既存仕様との整合
======================================================================

本Addendumは、以下の既存原則を変更しない。

    HOBS Object ≠ MT5 Object

    Delete ≠ State

    Delete ≠ Archive

    HOBS Object History
        ≠
    操作監査情報

また、

    Relation Removed

がRevision 3における一般的なHistoryイベントであることも変更しない。

本Addendumは、
その一般則に対して、

    「Deleteを原因としてRelationが消滅した場合」

という限定条件を追加するものである。


======================================================================
8. 本Addendumの境界
======================================================================

本Addendumでは、以下を定義しない。

    - Delete機構そのものの実装方式
    - Undo / Redoの具体的実装
    - 操作監査情報のデータモデル
    - 操作監査情報の保存期間
    - Repository実装
    - UI表示
    - Object Tree / Z-order
    - Provenance詳細

これらは後続仕様・実装監査の対象とする。


======================================================================
9. 確定事項
======================================================================

本部判断として、以下を確定する。

① Delete起因でRelationが消滅する場合、
   そのRelation Removedを存続するObjectの
   HOBS Object Historyには記録しない。

② DeleteされたObjectのHOBS Object Historyは、
   従来どおりObjectとともに消滅する。

③ Delete起因のRelation消滅について必要な操作記録を保持する場合、
   それはHOBS Object Historyとは別の監査情報として扱う。

④ 通常のRelation解除におけるRelation Removedについては、
   Revision 3のHistory規則を維持する。

⑤ 本AddendumはRevision 3本体をRevision 4へ変更するものではない。
