======================================================================
2. HOBS VWAPの基本原則
======================================================================

HOBS MT5版 VWAPでは、以下を基本原則として固定する。

1. 式は普遍である。
2. バーの存在は市場・データフィードごとに観測する。
3. 固定時刻はVWAPの本質ではない。

基本式：

TP = (H + L + C) / 3

HOBS VWAP = Σ(TP × V) / ΣV

H：High
L：Low
C：Close
V：Volume

MT5実装では、VとしてTick Volumeを使用する。

======================================================================
3. 増分更新式
======================================================================

新しいバーを計算対象へ追加する場合、累積状態を利用して更新する。

VWAP_new = (PV_old + (TP_new × V_new)) / (V_old + V_new)

ここで、

PV_old = Σ(TP × V)
V_old = ΣV

である。

HOBSにおいて重要なのは、単に式を実装することだけではない。

「どのバーを計算対象バーとして入力するか」が重要である。

固定する考え方：

「HOBSでは『式』より『入力するバー（計算対象バー）』が重要である。
存在するバーだけを計算対象にする。」

======================================================================
4. 時間とバー存在の考え方
======================================================================

VWAPの数学的定義そのものは、普遍的な固定時計時刻を必要としない。

一方、V4 LiteのMT5実装では、現在の実装仕様としてMT5サーバー／ブローカーのカレンダー日を計算窓として使用する。

この「00:00基準」はVWAPの意味そのものではなく、現在のMT5実装における計算窓の設定である。

したがって、

VWAPの本質 ≠ 00:00リセットという実装上の設定

と明確に区別する。

また、V4 Liteは実際にMT5データ系列として存在するバーを計算対象とし、存在しないバーを補間・生成しない。

MT5におけるチャート表示時刻と、バー時刻・サーバー時刻は同一概念として扱わない。

======================================================================
5. V4 Liteの設計
======================================================================

V4 Liteは、V3 Liteで確立した決定論的な計算基準を引き継いで設計された。

V3 Liteで確立した基本仕様：

・VWAPライン
・HLC3
・Tick Volume
・カレンダー日単位の計算窓
・実際に存在するMT5バーのみを使用
・補間なし
・現在バーを計算対象に含める
・累積計算
・不要な通知・メール・プッシュ等をコアから除外

V4 Liteでは、これに加えて計算効率と状態再利用を重視した。

累積状態として以下のバッファを保持する。

・CumPvBuffer
・CumVolBuffer
・CumTp2vBuffer

通常動作では、

・初回ロードまたは再計算時に履歴全体を計算
・通常ティックでは現在バーを再計算
・新バー発生時には直前バーまでの保存済み累積状態を利用
・その状態から新しい現在バーを追加
・現在バーの二重計上を防止

という構造を採用する。

MT5から再計算要求が発生した場合には、フル再計算へ戻れる構造を維持する。

======================================================================
6. 現在バーの扱い
======================================================================

現在バーは「形成中の観測対象」である。

形成中は、

・OHLC
・Tick Volume
・TP
・累積PV
・累積Volume
・VWAP

が変化し得る。

そのため、現在バーを一度計算したら固定するのではなく、形成中の現在バーとして更新する。

新バーへ切り替わった場合は、直前までの累積状態を新しい現在バーの開始状態として利用する。

この際、現在バーを二重に加算しないことをV4 Liteの重要な実装条件とする。

======================================================================
7. Debugと診断機能の分離
======================================================================

通常のV4 Lite運用では、

InpPrintDebug = false

を基本とする。

数値監査では、通常版とは別の診断ビルドを使用した。

診断ビルドでは、内部計算とは独立して、

independent_cum_pv = old_cum_pv + tp_new × v_new

independent_cum_vol = old_cum_vol + v_new

independent_vwap = independent_cum_pv / independent_cum_vol

を計算し、V4 Lite内部状態と比較した。

この構造により、

「通常計算ロジック」と「検証用の独立計算」

を分離した。

12. V4 Lite 凍結判定
======================================================================

V4 Liteは今後、

「VERIFIED BASELINE（検証済み基準実装）」

として扱う。

検証済みのコアロジックについて、機能追加を理由とした安易な変更を行わない。

変更が必要になった場合は、

変更理由 → 仕様化 → 実装 → 独立検証 → レビュー

の順で扱う。

V4 Liteで凍結する基準：

・HOBS VWAPの数学的定義
・HLC3計算
・Tick Volume入力
・実際に存在するバーを計算対象とすること
・MT5サーバー／ブローカーのバー日付を基準としたカレンダー日計算窓（V4 Lite実装仕様）
・現在バーを計算対象に含めること
・累積状態を利用した増分計算
・新バー遷移
・現在バーの二重計上防止
・存在しないバーを補間しないこと
・通常運用時の不要な診断出力を行わないこと

V4 Liteは、次のProduction HOBS VWAPを設計する際の「数値的な基準実装」とする。

14. HOBSにおけるVWAPの位置づけ
======================================================================

HOBS VWAPは最終目的ではない。

VWAPはHOBSの市場観測を構成する一つの観測単位である。

将来的には、

VWAP ＋ Price ＋ Volume ＋ Time ＋ Structure ＋ Psychology
↓
HOBS Market Observation

という接続を目指す。

VWAPは「平均コストの記憶」を観測する。

そのため、VWAP自身はできるだけ、

・数学的に単純
・検証可能
・再現可能
・監査可能
・不要な売買ロジックから独立

であることを維持する。

HOBS全体の方向性：

「見る相場から、聴く相場へ。」
